# المرحلة الأولى — اختبارات #802 فقط

لم يُعدَّل أي كود إنتاجي. لم تُشغَّل أوامر أو اختبارات أو اتصالات PostgreSQL؛ التنفيذ للمشرف بعد قراءة المصدر.

## التغطية

- اختبار domain لكل حقل من الهوية الخماسية منفرداً، مع تجاهل التعارض المساوي/الأقدم، ورفض دفعة مختلطة، وقبول التغييرات القابلة للتعديل والشهر الجديد.
- اختبار PostgreSQL للمسار الحقيقي من المستهلك إلى التخزين وعلامة التسليم، مع مقارنة الرؤوس والأنصبة وكل أعمدة الكشوف والعلامات قبل الرفض وبعده.
- رصد طلب المنطقة الزمنية عند منفذها، ورصد طلب قفل الشهر بتغليف المنفذ الحقيقي دون استبدال التخزين؛ المقارنة خارج المعاملة تثبت أن الصفر ليس نتيجة rollback فقط.
- انتقال النشاط في PostgreSQL يستخدم فرعاً وخدمة ومنفّذة من النشاط البديل نفسه حتى لا يخفي FK غير صالح عيب الهوية. اختبار domain يعزل حقل النشاط وحده.
- عقود `ServiceSessionRecorded` و`ServiceSessionLinesAdded` تقبل `revision=1` فقط. لذلك دفعة المراجعات الأحدث تُختبر عند مدخل `ProjectServiceLines.execute` الحقيقي داخل PostgreSQL، بعد تحليل كل لقطة منفردة بالعقد وتوحيدها بالغلاف المطابق؛ لا يُرسل غلاف دفعة غير صالح للمستهلك. رفض التسليم بلا علامة يُثبت منفرداً لكل تعارض هوية.

## أوامر المشرف

من جذر worktree، بعد تفعيل lane الخاص `batch-20261110-802` على `127.0.0.1:55410` بالآلية المعتمدة، دون استعارة بيئة من مهمة أخرى:

```powershell
pnpm --filter @pospay/worker exec vitest run src/modules/commissions/domain/__tests__/commission-line-identity.spec.ts
pnpm --filter @pospay/worker exec vitest run src/modules/commissions/__tests__/commission-line-projection-identity.spec.ts
```

الـ RED المتوقع من قراءة baseline، وليس نتيجة تشغيل: ستة اختبارات domain ترفض غياب خطأ الهوية (الخمسة والدفعة المختلطة)، وسبعة اختبارات PostgreSQL تفشل بسبب استمرار قبول الهوية أو طلب التقويم/قفل الشهر أو غياب الهوية من الرأس المقروء (الخمسة والدفعة وقراءة الرأس). باقي الحالات ضوابط يُتوقع نجاحها. إعداد worker يشغّل global setup الخاص بقاعدة البيانات حتى عند اختيار ملف domain.
