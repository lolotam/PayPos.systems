## Astra output (verbatim)

1. **P1 blocking — `plan-42-3b1.md` §2.1: request FKs contradict worker refusals.** Customer/type/seller FKs reject unknown or out-of-scope IDs during acceptance. SA-08’s seeded pending requests cannot exist, so the worker cannot return the promised named failures. **Fix:** distinguish submitted references from validated identities: retain submitted IDs without those FKs on the request; enforce scoped FKs on the resulting entitlement. Reconcile the schema/spec and test acceptance followed by each worker refusal.

2. **P1 blocking — §2.2: domain move leaves broken imports.** The five-file move excludes `PackageSaleError`, `PackageSalePricingError`, `PackageSaleIdentityInvariantError`, `SessionEmployee` and `SessionService`. Meanwhile API `ports/session-readers.port.ts` still imports the moved `package-sale-types.ts`. Rewriting imports alone cannot resolve these dependencies without forbidden worker-to-API imports. **Fix:** explicitly assign worker-owned errors/types, retain an API-local catalog projection type, and enumerate all affected imports. Require API and worker typechecks on **42-3b1a independently**.

3. **P1 blocking — §2.3: copying the catalog SQL preserves the missing stop check.** The current `package-type-sale.reader.ts` does not select `selling_stopped_at`; `SalePackageType` lacks it, and `PackageSaleErrorCode` lacks `PACKAGE_TYPE_NOT_SELLABLE`. Exact copying plus unchanged rules cannot satisfy FR-018b or the promised stop race. **Fix:** make 33b’s schema change an explicit dependency; add the field and named refusal, checked under the type lock **before** revision comparison. Test both stop/sale lock orders.

4. **P1 blocking — §§2.3, 6: startup wiring is incomplete.** The existing worker starts transports explicitly in `apps/worker/src/main.ts`; module exports do not start processors automatically. The plan names only `orders.module.ts` for readiness/close and omits composition-root changes needed to supply IDs, clock and measured transaction budget. **Fix:** include the root/export/config changes, transport delivery chain, known-event registration, recovery registration, readiness and shutdown. Test delivery through the actual composed worker.

5. **P1 blocking — §3: merge order substitutes for deployment order.** The proposed split requires recovery to *merge* before 42-3b2, but ADR-0034 requires the complete consumer to be **deployed and ready** first. With optional 42-3b1c, “42-3b1 deployed” is also ambiguous. **Fix:** gate the producer on a verified deployed SHA containing both execution and recovery; record processor readiness. Define that SHA as the worker rollback floor while the producer remains live.

6. **P2 should fix — §2.1: terminal-state insertion bypasses the transition trigger.** `pospay_app` receives unrestricted `INSERT`; the guard applies only to updates. A direct insert can therefore create a structurally valid `completed` or `failed` request without ever passing through `pending`. **Fix:** enforce initial state on insert: `pending`, with null entitlement, error fields and `finished_at`. Add direct-SQL negative tests under `pospay_app`.

7. **P2 should fix — §2.1: terminal field invariants are incomplete.** The listed checks tie `entitlement_id` and `error_code` to status, but do not explicitly constrain `error_details` or `finished_at`. A pending/completed row could carry failure details, or a finished row lack its completion timestamp. **Fix:** specify a complete state-shape constraint, including null handling, and test every invalid combination.

8. **P2 should fix — §2.4: sequential replay tests miss concurrent execution and uncertain commit.** Replaying already-finished requests does not prove two workers handling the same pending request serialize correctly. Nor does a generic “unknown failure” test cover a successful COMMIT whose acknowledgement is lost. **Fix:** add real-DB concurrent duplicate execution and post-commit acknowledgement-failure tests. Assert exactly one entitlement, audit and event; a committed request must remain `completed` despite retry/finalization.

9. **P2 should fix — §2.4: frozen acceptance context lacks regression coverage.** Tests mention the frozen discount value and `recorded_at`, but not changes between acceptance and execution. Accidental reauthorization, fresh-limit reads or execution-time defaults could pass the proposed cases. **Fix:** seed acceptance, revoke recorder authority/change its limit, advance the injected clock across a month boundary, then execute. Assert accepted authority/limit remain binding and omitted `sold_at`, window validation and expiry use `recorded_at`.
