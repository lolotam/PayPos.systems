## Implementation sequence

1. **Template.** Assemble eight English headers in FR-004 order, attach Arabic comments, and write the rule, boolean and open-category reference data with ExcelJS. Reuse one business-scoped category lookup for template and preview. Return the existing serviceImportTemplate shape. Reserve one data and one reference sheet in WorkbookBounds. Run the actual generated bytes through the guarded reader. P-3 allows 35,416 reference positions total and 6,552 data rows per reference sheet. Count all rule and boolean rows, heading rows and the actual used dimensions. Enforce the compressed size and other guard limits too. Refuse the download with a clear error when the complete reference exceeds a reader guard.
2. **Preview, rows and status.** Bind catalog-owned file-facts and object-bytes ports at composition, retaining the file boundary of D-4. Verify caller/company/business ownership, READY status, XLSX MIME and size before fetching bytes. Read storage outside a database transaction. Translate storage/parse errors at the adapter; preserve staff behavior. Extend the package reader with a compatible opt-in result containing aligned values and number formats from one guarded ExcelJS pass. Derive header text from that matrix, call serviceImportExpectedHeaders and readSheet, use sourceRows to join original row numbers to tagged rows, then call mapServiceImportRows with its synchronous category resolver. Do not reparse the ZIP or index tagged rows by dense row number. Preserve unchanged package callers.
3. Build the resolver from open same-business English category keys. Match the mapper’s returned keys against all same-business service names in a bounded number of queries, including closed services. Apply IMPORT_SERVICE_EXISTS even on otherwise invalid keyed rows, retain in-file errors and filter affected rows out of the clean projection. Use the same key implementation across runtime boundaries via a permitted shared home, or demonstrate SQL equivalence on actual Postgres; test the checked-in Unicode vectors and differences in collation/whitespace. Keep pure serviceTerms and per-field validation in the existing mapper. Save ready preview, all errors and immutable clean rows in one tenant write. Page the clean rows by original row number; apply creator, business, company and entity filters before projecting. Keep status a small projection. Register only the four live HTTP/OpenAPI operations and regenerate clients.
4. **Worker.** Extend catalog event delivery and dynamic known-event registration together. Accept only the matching request event, route it to service-import-commit with stable job identity and tenant envelope, acknowledge on successful enqueue and propagate delivery failure. Verify id-only payload. Seed the request and event in local integration tests. In one withTenant transaction lock the scoped services preview FOR UPDATE, skip other states and entities, validate zero errors and requested_at strictly before expires_at. Use the stored request time even if execution is delayed. Check business existence. Acquire a transaction-scoped company/business/import advisory lock before the decisive name read. Lock deduplicated referenced category IDs in ascending order FOR SHARE, verify each still exists in this business and is open, then insert. Scope each statement, including failure writes. A category rename leaves the validated ID intact. Preserve resolved category IDs, service money representation, normalized commission columns, threshold flag, duration, category and revision 1; generate service/audit IDs through injected IdGenerator and use one injected clock instant for writes. Discard preview display fields. Audit using the manual-create snapshot shape, preview.created_by and no before value. Persist created_count, committed_at and committed together with all rows and audits.
5. Roll back the complete transaction on failure. After rollback, conditionally fail only the still-requested matching preview in its own tenant transaction; preserve immutable errors/rows. Name race gives IMPORT_SERVICE_EXISTS, category loss/closure gives IMPORT_CATEGORY_NOT_FOUND, invalid request timing gives IMPORT_PREVIEW_EXPIRED. Unexpected failures follow FR-009’s three retries, then IMPORT_COMMIT_FAILED. Demonstrate terminal replay, rollback after an injected mid-write failure, and failure marking racing a successful retry. Worker performs no file read or new authorization. Manual writes remain under SV-02, which permits same-name manual services even during an import.
