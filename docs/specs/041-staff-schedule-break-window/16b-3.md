# Row 16b-3 — break return at another branch

BW-Q10: Abu Salem's pick, approved by Waleed on 2026-10-11, supersedes the same-branch return
rule in 16b-2. A non-voided clock-in after the latest eligible break-out, up to the worker's
locked decision instant, counts at any branch of the same business. The first such clock-in
identifies the return branch. A same-branch return remains quiet; no return keeps the existing alert.

The departure branch's existing manager recipients receive `break_returned_other_branch`, revision 1:
«{{employee_name_ar}} رجعت من البريك في فرع {{branch_name_ar}}» /
"{{employee_name_en}} returned from the break at {{branch_name_en}}".
Names are the employee and destination branch, with the existing safe-name fallbacks.

The existing `ShiftBreakNotReturned` outbox envelope is retained for compatibility with the current
consumer and dispatcher. Additive `notice_kind` distinguishes the return notice from the missing-return
alert; `returned_branch_id` and `returned_at` describe the return. Its `branch_id` stays the departure
branch. The existing ledger's employee/shift-start unique key, State lock, transaction and recipient
groups prevent reruns and concurrent jobs from creating duplicates. An alert already committed is not
retracted or replaced. No migration or index is needed: the employee/date index still bounds the probe,
with same-business filtering; its EXPLAIN ANALYZE assertion is retained.

Lateness (FR-010) remains unchanged. `attendance-context.adapter.ts` matches earlier closed sessions by
branch and scheduled end; `clock-break-return.spec.ts` proves an earlier session at another branch
does not count for lateness (14:05 versus a 09:00 start = 305 minutes). This row changes only the worker
notification decision, not that API rule, stored lateness, attendance sessions or exceptions.

Tests cover destination text and departure recipients, outbox/in-app delivery and redelivery, reruns,
concurrent workers, same-branch silence, missing-return alert, invalid/voided return exclusion and
the inclusive decision-instant boundary.
