# API contract: 61-2a + 62-2e

Design, not code. The Zod schemas live in `packages/contracts`; the OpenAPI file and the three generated clients are
regenerated by the implementer (`pnpm contracts:openapi`, then `api:generate` in `apps/admin`, `apps/pos` and
`apps/menu`).
Shapes marked **new** do not exist at the pin.

## 1. `GET /v1/staff/me/rating-summary` — **new** (61-2a)

- Module: API `customers`, `queries/`. Zod: `packages/contracts/src/customers/own-rating-summary.ts` (+ `-openapi.ts`,
  registered in `packages/contracts/src/openapi.ts` like `ownTipsPaths`).
- Security in OpenAPI: `PersonalStaffSession` only (the name `own-tips-openapi.ts` uses for that scheme). Decorators:
  `@Authenticated()` + `@SetMetadata(PERSONAL_ROUTE, true)`, the pattern of
  `apps/api/src/modules/staff/http/my-schedule.controller.ts`. No `STAFF_ROUTE`, no `@PrivateViewRoute()`.
- Query: none. A strict empty object; any key is refused.
- Response 200, header `Cache-Control: no-store`, discriminated on `visibility`:

| `visibility` | Other fields | Meaning |
|---|---|---|
| `HIDDEN` | none (strict) | `rating_average` is not an allowed staff column. Always the case until 61-3 |
| `VISIBLE` | `average`: string matching `^(?:[1-4]\.[0-9]|5\.0)$`, or `null` · `count`: integer ≥ 0 | Own attributions in the current business-timezone month |

- Invariant enforced by the schema: `count = 0` ⇔ `average = null`.
- The schema is strict: a comment, a customer, a star list or an employee id cannot be added without a contract change.

**Order of checks (first failure wins):**

| # | Check | Outcome |
|---|---|---|
| 1 | Personal staff session (`SessionGuard` → `personalSessionRequest`). An admin session or a reception-device operator session is not a personal session | 401 `UNAUTHENTICATED` (the implementer asserts the guard's actual refusal for each foreign session kind) |
| 2 | — (no private-view window: the reception-device path is not offered) | — |
| 3 | Database available | `NOT_READY` |
| 4 | In the one `withTenant(companyId, …, { userId })` transaction: business exists in the company and has an active branch; the caller's own eligible employee; membership; feature `customers`; `read:ratings:own` | 403 `FORBIDDEN` |
| 5 | The raw query names `employee_id`, `branch_id`, `business_id` or `company_id` | 403 `FORBIDDEN` |
| 6 | Any other query key | `VALIDATION_FAILED` |
| 7 | `rating_average` not in the allowed staff columns | 200 `{ "visibility": "HIDDEN" }`, no rating row read |
| 8 | Aggregate | 200 `VISIBLE` |

Examples (synthetic):

```json
{ "visibility": "HIDDEN" }
{ "visibility": "VISIBLE", "average": "4.5", "count": 2 }
{ "visibility": "VISIBLE", "average": null, "count": 0 }
```

## 2. `POST /v1/businesses/:businessId/employees/:employeeId/documents` — exists, request extended (62-2e)

`recordEmployeeDocumentInput` gains one optional key:

| Key | Type | Rule |
|---|---|---|
| `document_number` | string, `null`, or omitted | When a string: trimmed, then 1–64 characters, no control characters. Omitted = `null` = no number |

- `""` or whitespace-only → `VALIDATION_FAILED` (after trimming the length is 0). The error lists the path and the
  issue code only, never the value (existing `ZodValidationPipe` behaviour).
- Response: `EmployeeDocument`, **unchanged — no `document_number`** (research D-9).
- `Idempotency-Key`, permissions (`manage:files:business` with `read:files:business`), audit action and the
  `EmployeeDocumentRecorded` payload are unchanged. The fingerprint is the existing SHA-256 of method, route and body.

## 3. `GET /v1/businesses/:businessId/employees/:employeeId/documents` — exists, response extended (62-2e)

Each element of `items` gains `document_number: string | null`. The list item becomes its own schema
(`EmployeeDocumentListItem` = the `EmployeeDocument` fields + `document_number`), so the `POST` response schema stays
without it. Access rules are unchanged: no `read:files:business` → 404 `NOT_FOUND`.

## 4. `GET /v1/businesses/:businessId/employee-document-numbers?ids=…` — **new** (62-2e)

- Module: API `staff`, `queries/employee-document-numbers.query.ts`; its own controller.
- Guards: `@Authenticated()` + `SelectedCompanyGuard` (as the documents list). `Cache-Control: no-store`.
- Query: one CSV string `ids` containing 1 to 20 distinct UUIDs. Document that CSV in OpenAPI and verify
  serialization from the generated client through Fastify. Canonicalize UUID case before checking duplicates.
  Reject repeated query parameters and unknown keys.
- Response 200:

```json
{ "items": [ { "document_id": "018f6f6e-0000-7000-8000-000000000001", "document_number": "SYN-DOC-0001" } ] }
```

`items` holds **only** the requested ids that satisfy all of: same company (RLS and the explicit predicate), business
= the path's business, the document is current (`replaced_at IS NULL`), its employee is not deleted, and
`document_number IS NOT NULL`. Every other requested id is absent, with no reason given.

**Order of checks:**

| # | Check | Outcome |
|---|---|---|
| 1 | Session, selected company | 401 / the guard's existing refusal |
| 2 | `ids` shape | `VALIDATION_FAILED` |
| 3 | Database available | `NOT_READY` |
| 4 | In one `withTenant` transaction, **before any document row is read**: `EmployeeDocumentReadAccess.check(tx, companyId, userId, businessId)` → `read` false | 404 `NOT_FOUND`, identical for every `ids` value |
| 5 | Feature `staff` disabled | `FEATURE_DISABLED` |
| 6 | Read | 200 |

## 5. Admin use of §4

`apps/admin/src/notifications/api/use-document-numbers.ts` (**new**): for the bell items on screen whose
`template_key` is `document_expiring` and whose `business_id` is not null, one request per business while the panel
is open. Key by company, user, business and normalized ids. Cancel and remove obsolete requests and data on close
or scope change. Pass AbortSignal and ignore late results. Revalidate on reopen, notification refresh and known
permission changes. Display only current successful data; refetch, pending, error or a missing id falls back to the
existing text. Keep the numbers out of persistent storage and the inbox cache.

`documentExpiringParameters` (six parameters, the last is `document_id`), the `document_expiring` template (revision
1), `EmployeeDocumentRecorded`, `DocumentExpiring`, the inbox routes, every permission and role default.
